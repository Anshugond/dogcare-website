MASTER DIGITAL STORE — CLOUDFLARE PAGES + EASEBUZZ + D1 + PRIVATE R2
Version: reusable multi-product foundation

WHAT THIS PROJECT DOES
- Keeps the existing Dog Care homepage at /
- Supports multiple product landing pages at /<slug> using D1 records
- Admin at /admin.html (also /admin alias)
- Admin can create/edit/publish draft pages, set product prices, order bumps,
  upload main and bump PDFs to private R2, upload hero images, set per-page Meta Pixel ID
- Shared Easebuzz payment/verification/download APIs are retained from the supplied
  working Dog Care project. Payment files were not intentionally redesigned here.
- Admin API includes recent order listing (up to 500 records).

IMPORTANT LIMITATION
This is a reusable multi-product base, not a no-code drag-and-drop page designer.
The page editor provides content fields, feature/FAQ sections, a preview, pricing,
order bump and asset upload. Custom layouts beyond these controls require code/design work.
The project package cannot verify your live Cloudflare bindings, secrets, D1 state,
Easebuzz merchant configuration, or live payment status. Do not assume deployment is
production-verified until you test it in your own Cloudflare account.

CLOUDFLARE PAGES BUILD SETTINGS
- Framework preset: None
- Build command: blank

- Root directory: blank

REQUIRED BINDINGS
- D1 binding name: ORDERS_DB -> existing database dogcare-orders
- R2 binding name: EBOOKS -> existing private bucket dogcare-ebooks

REQUIRED SECRETS / VARIABLES (Production and Preview as needed)
- EASEBUZZ_KEY: your Easebuzz merchant key (Secret recommended)
- EASEBUZZ_SALT: Secret only; never put in source code
- EASEBUZZ_ENV: live or test; must match credentials
- ADMIN_PASSWORD: your chosen strong admin login password
- ADMIN_SECRET: independent random secret, at least 32 random characters
Do not put any secret in GitHub or this ZIP. Keep existing working values in Cloudflare.

DATABASE
The supplied project expects both migrations to have already been applied:
1. migrations/0001_orders.sql (base orders/download_tokens tables)
2. migrations/0002_landing_builder.sql (landing_pages + page metadata columns)
If your live D1 already has these tables/columns, do not run ALTER migration 0002 again.
If uncertain, inspect D1 schema before applying. Never reset or delete the production database.

PRODUCT FILES
- Admin uploads PDF assets to the private EBOOKS R2 bucket.
- Main PDF and optional bump PDF object keys are saved with each landing page.
- Do not make the R2 bucket public.
- Download links are generated by the existing secure payment/download flow.

HOW TO ADD A NEW PRODUCT
1. Open https://YOUR-DOMAIN/admin.html and sign in with ADMIN_PASSWORD.
2. Click + New landing page.
3. Enter product name and URL slug (e.g. editing-bundle).
4. Set product title, price, upload main PDF, optionally enable bump and upload bump PDF.
5. Customize headline, subtitle, accent color, hero image, Pixel ID and sections.
6. Save draft, inspect preview, then Publish.
7. The product page is https://YOUR-DOMAIN/<slug>.
8. Test the payment flow with Easebuzz sandbox before advertising. A live payment charges real money.

DOG CARE EXISTING PAGE
The existing index.html at / is preserved as supplied. The multi-product page system uses
D1-published slugs (e.g. /dogcare). If the existing Dog Care design currently lives only
in index.html and has not been created as a D1 landing_pages record, it will not magically
be copied into /dogcare by this package. That migration requires transferring its content
and assets into a published D1 page configuration; preserve the original homepage meanwhile.

DOMAIN
Connect your domain once in Cloudflare Pages > Custom domains. Each published slug then
uses the same domain path, e.g. anshugor.com/dogcare and anshugor.com/editing-bundle.

ADMIN ROUTING
_routes.json excludes only /admin.html from Functions so Cloudflare serves the static admin
file directly. /admin remains handled by functions/admin.js and redirects to /admin.html.

PAYMENT SAFETY
- Do not modify Easebuzz secrets in this package.
- Never share merchant salt/passwords in chat or screenshots.
- Never test a live payment unless you intend to make a real charge.
- Confirm successful payment, failed payment, amount validation, bump selection,
  and download expiry in sandbox before production campaigns.
